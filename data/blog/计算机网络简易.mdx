# 7 层

## 物理层

物理层是直接和物理介质打交道的。
物理层的设备网卡，网线，集线器，中继器，调制解调器
物理层信道

有线信道：明线

指的是类似电线杆上的架空线缆。包括

1. 对称线缆

2. 同轴电缆

3. 光纤

在这一层通过（光、电、无线电波），获取它们对于的传输信号，电压，转换成 01010101 但是数据还未组织，它们的单位为 bit，在这一层主要就是传输比特流。

## 数据链路层

建立逻辑连接、进行硬件地址寻址、差错校验等功能。
将比特组合成字节进而组合成帧，用 MAC 地址访问介质。

MAC 地址： 每个网卡的唯一标识
有了MAC 地址就能知道谁是接收者，谁是发送者，并且知道了数据的内容且进行了分组。

## 网络层

比较复杂

主要做了：

1. 寻址：对网络层而言使用 IP 地址来唯一标识互联网上的设备，网络层依靠 IP 地址进行相互通信

2. 路由：在同一个网络中的内部通信并不需要网络层设备，仅仅靠数据链路层就可以完成相互通信，对于不同的网络之间相互通信则必须借助路由器等三层设备，这一层经常被叫做数据包。

## 传输层

主要定义 端口号 ，控流以及校验，并有我们熟知的 TCP UDP

TCP 是面向连接的协议并且 TCP 是可靠的。

因为 TCP 有三次握手建立连接和 四次挥手关闭连接，但是这样会降低速度。

UDP 具有较好的实时性，效率比 TCP 高。

UDP 没有三次握手，四次挥手，不稳定。但是速度快 常用于指标，游戏

## 表示层

2. 表示层还会对图片文件等格式进行解码和编码， 例如 JEPG 、 ASCII 图片。

# 三次握手

1. Seq 序列号
2. ack 确认号
3. ACK 确认序列号有效
4. SYN 发起新连接

客户端 SYN : seq --> 服务端
\<-- SYN 服务端seq + ACK = 客户端seq + 1
--> ACK seq = 客户端seq + 1 ack = 服务端 seq + 1

# 四次挥手

1. FIN 完成

客户端 [ESTABLISHED] FIN seq = x -> 服务端 [ESTABLISHED]
客户端 [FIN_WAIT_1] \<- ACK ack = x + 1 服务端[CLOSE_WAIT]
客户端[FIN_WAIT_2] \<- FIN ACK seq = w ack = x + 1 服务端[LAST_ACK]
客户端 [TIME_WAIT 超时等待状态 2MSL] ACK seq = x + 1 ack = w + 1 -> 服务端[LAST_ACK]
客户端 [CLOSE] 服务端[CLOSE]

# 分发网络 CDN

主要作用在 DNS 寻址过程中，网站把这个域名用 CNAME 指向 CDN 服务商的域名，让其不访问权威域名服务器而是交给 CDN 调度网络 (GSLB).

GLSB 会根据用户位置、运营商、节点负载等，返回一个最合适 的边缘节点

浏览器拿到 IP，和边缘节点建立连接、发请求

节点有缓存就直接返回；没有就回源，从源站拿到资源后缓存起来再返回

1. 加速访问
2. 减轻源站压力
3. 提高可用性

# 跨域

有四种解决方法

什么是跨域？
浏览器请求时， 协议、域名、端口 有一个不同就是跨域。

Curl 命令等不受限制。

## JSONP

原理：通过`script`的src 不受同源策略的限制，可以跨域请求数据，但是只能发送 Get 请求

缺点：只能发送 GET 请求，不安全，不易维护

后端返回的是一个函数 但是这个函数是在前端定义的，他会把值注入到这个函数的参数里

```js
const jsonp = (name) => {
  let script = document.createElement('script')
  script.src = 'http://localhost:3000/api/jsonp?callback=' + name
  document.body.appendChild(script)
  return new Promise((resolve) => {
    window[name] = (data) => {
      resolve(data)
    }
  })
}

jsonp(`callback${new Date().getTime()}`).then((res) => {
  console.log(res)
})
```

# Fetch

`await fetch()` 获取的是流，而并不是最后的`response`。

因此，还需要 `await response.json()`才能获取最终答案。

## 实现下载进度：

Fetch 获取下载进度，就是通过 ReadableStream 逐块读取响应体，累计已接收的字节数，再除以响应体的总字节数。

但是如果服务器不返回 `Content-Length`时，则无法实现。比如： 流式传输

```js
const response = await fetch('/api/file')

const total = Number(response.headers.get('Content-Length'))

const reader = response.body.getReader()

let received = 0

while (true) {
  const { done, value } = await reader.read()

  if (done) break

  received += value.byteLength

  console.log(`下载进度：${((received / total) * 100).toFixed(2)}%`)
}
```

## 取消请求

```js
const controller = new AbortController()

const signal = controller.signal

fetch('/api/users', { signal })
  .then((res) => res.json())
  .then((data) => console.log(data))
  .catch((err) => {
    if (err.name === 'AbortError') {
      console.log('请求被取消')
    }
  })

// 取消请求
controller.abort()
```

# SSE 服务端事件

基于 HTTP 协议，利用其长连接特性，在客户端与服务端之间建立一条持久化连接，并通过这条连接实现服务端向客户端的实时数据推送。

## EventSource()

1. URL 服务连接地址
2. Options
3. close()事件
4. onopen事件
5. onerror 事件

### 例子

```js
app.get('/api/sse', (req, res) => {
  // 1. 设置 SSE 响应头
  res.set({
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
  })

  // 2. 读取文件
  const txt = fs.readFileSync('./index.txt', 'utf8')
  const arr = Array.from(txt)
  let current = 0

  // 3. 每隔 300ms 发送一个字符
  const timer = setInterval(() => {
    if (current < arr.length) {
      res.write(`data: ${JSON.stringify(arr[current++])}\n\n`)
    } else {
      clearInterval(timer)
      res.end()
    }
  }, 300)

  // 4. 客户端断开连接时清理定时器
  res.on('close', () => {
    clearInterval(timer)
  })
})
```

# HTTP & HTTPS

# XSS 攻击

跨站脚本攻击

## 反射型 XSS

放射型 XSS 只是简单的把用户 输入的数据从服务器反射给用户浏览器，要利用过这个漏洞，攻击者必须以某种方式
诱导用户访问一个精心设计的 URL，才能实时攻击
`http://127.0.0.1:5500/index.html?a=<script>alert(1)</script>

## 存储型 XSS

存储型，主要发生在由社区内容驱动的网站或 Web 网页。

黑客提交 XSS 漏洞利用代码到一个网站上其他用户可能访问的地方，可能是评论区、聊天室等。

一旦用户访问，执行是自动的。

## Dom型XSS

里用了 Web 应用程序中的 JS 等脚本语言与 HTML 的交互形式及 DOM 文档对象模型操作实现。

与别的 XSS 不同，DOM 型 XSS 不会触发 HTTP 请求或响应过程，它的攻击载荷不会被传递到服务端 ，而是 直接 在客户端执行，使其更难检查和防范

比如： `InnerHTML`直接 把用户输入内容加载到 DOM 上，不过滤
