# Nemo影片 11/09

Mini-Pi 、 抽奖被问穿了

1. 请你简单做一下自我介绍。

2. 你基于 Pi 开发的 Coding Agent 是什么时候做的？你目前对这个项目的熟悉程度怎么样？

3. 你能详细介绍一下自己开发的 Coding Agent 吗？它主要具备哪些功能和能力？

4. 你基于 Pi 的 Runtime 实现了哪些模块和功能？最终做出来的 Agent 能做什么？能接入哪些模型？

5. 你在工具调用安全性方面做了哪些设计？具体的实现思路是什么？

6. 除了正则匹配之外，你还采用了哪些安全控制手段？

7. 当 Agent 准备执行危险命令时，你是如何判断是否需要用户授权的？

8. 对于危险操作，你要求用户每次授权，还是支持白名单配置？具体是怎么实现的？

9. 用户的授权记录是会话级别（Session），还是全局级别？这两种授权范围分别怎么处理？

10. 假设用户已经授权某个危险命令，你会把这个授权记录存储在哪里？是放在 Session 的上下文中吗？

11. 如果用户不希望每次执行某个命令都被询问，而是希望配置一个长期生效的白名单，你会怎么设计？

12. 如果授权记录保存在上下文中，而 Agent 执行过程中发生上下文截断，导致之前的授权信息被遗忘，你会怎么解决？

13. 你开发的 Agent 有没有进行过完整的验收和测试？

14. 你平时使用 Claude Code、Codex 等工具时，有没有自己总结或编写 Skills 的习惯？

15. 假设需要针对业务场景抽象一个 Skill，你会怎么设计？什么时候应该使用 Markdown 描述流程，什么时候应该使用脚本或工具？

16. 当你完成一个 Skill 的设计后，在正式交付给用户之前，还需要做哪些事情？

17. 你平时使用别人提供的 Skills 时，有没有遇到过什么问题？你觉得应该如何处理？

18. 如果 Agent 面向大量用户，不同用户的操作系统、软件环境和机器配置都不一样，而 Skills 又需要执行脚本或命令，你会如何解决环境兼容性问题？

19. 如果用户处于网络隔离环境，无法使用远程 MCP 服务，有没有本地运行的解决方案？

20. 你了解 Claude Code、Codex、Cursor 等工具一般是如何处理执行环境问题的吗？

21. 如果一个 Skill 需要运行 Python 脚本，但用户电脑没有安装 Python，应该如何处理？

22. 你了解 Sandbox（沙箱）吗？是否可以让 Agent 在独立的沙箱环境中执行任务？

23. 除了统一运行环境，沙箱还有哪些优点？

24. 你在龙腾科技实习期间主要负责前端工作，是吗？抽奖项目是否也涉及后端开发？

25. 你能介绍一下抽奖系统中防止并发导致库存超发的设计吗？具体是怎么实现的？

26. 假设有十个人同时请求抽奖，你会执行哪些数据库操作？如何根据 updateCount 判断库存扣减成功还是失败？

27. 能不能详细描述一次抽奖请求的完整执行流程？包括请求进入后操作哪些数据表、更新哪些字段，以及如何根据数据库更新结果判断抽奖是否成功？

28. 假设一个用户使用十台设备同时发起抽奖请求，而系统规定每个人只能中奖一次，是否可能因为并发导致这个用户最终获得十个奖品？

29. 如果十个并发请求同时查询用户的中奖记录，并且都发现该用户尚未中奖，是否可能让所有请求都通过中奖资格校验？

30. 如果实际发生了同一个用户通过并发请求获得多个奖品的问题，你会如何修改系统，保证每个用户最多只能中奖一次？

31. 如果要限制同一用户在第一次抽奖请求完成之前不能再次抽奖，你会通过什么技术手段实现？
