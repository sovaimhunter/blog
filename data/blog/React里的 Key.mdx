# Key

为什么我们常说 React 中的 Key 十分重要。
因为它与 React 的协调，也就是`render`阶段关系密切。用于生成新的`WIP Fiber`树。

我们先讲讲`diff`

## Diff

Diff 的比较只需要`key ` 和`type`两个。
首先我们需要明确一点，新旧的比较并不是 Fiber 的比较，而是 React Element和 Fiber 的比较。也就是对象数组和 Fiber 树这个链表的比较。

Diff 算法本身是有性能损耗的。即使是最前沿的算法，完整的对比两棵树也会达到 O(n^3)的时间复杂度。

因此，React 为 Diff算法做了三个限制：

1. 只对同级别元素进行 Diff，如果一个 Dom 元素在前后两次更新中跨越了层级，那么 React 不会尝试复用。
2. 两个不同类型的元素会产生不同的树。比如，元素`div ` 变成`p`，那么 React 会直接销毁`div`以及子孙元素，新建`p`以及其子孙元素
3. 开发者可以使用 key 来表示哪些子元素能保持稳定

第二，Diff 算是只适用于同级元素，也就是同一父元素下才使用。

### 单节点Diff

单节点指的是新节点为单一节点，但是旧节点的数量是不一定的。
单节点Diff 是否能够复用遵循以下流程：

1. Key 是否相同
   1. 如果更新前没有设置 key，那么 key 就是 null，也是属于相同情况
   2. key 相同，就进入到步骤二
   3. key 不同，无需判断 type，直接不能复用，如果有`sibling`就去判断兄弟节点是否能复用
2. key 相同，再判断 type 是否相同
   1. 如果 type 相同，那么就复用
   2. 如果 type 不同，无法复用（兄弟节点也删除）

### 多节点Diff

多节点Diff，就是新节点是多个。
多节点 Diff 分两轮

1. 第一轮遍历会尝试逐个的复用节点
2. 第二轮遍历处理上一轮遍历中没有处理完的节点

#### 第一轮

第一轮遍历会从前往后一次进行遍历，存在三种情况

1. 如果 Key type 都一样，复用。

2. 如果key 相同，而 type 不同，这个时候就会根据 ReactELement 里的type 生成一个全新的 Fiber 节点，旧的 Fiber 放在`deletions`数组里，回头统一删除，然后继续遍历

3. 如果新旧节点 key type 都不同，结束遍历。

#### 第二轮

如果第一轮遍历被提前终止了，意味着 遇到key type不同的 Fiber 节点了。
此时就会采取第二轮遍历。

第二轮遍历会处理三种情况：

1. 只剩旧子节点：将旧的子节点添加到`deletions`数组里面直接删除掉
2. 只剩下新的 ReactElement： 根据 ReactELement 元素来创建 FiberNode 节点
3. 新旧节点都有剩余：会将剩余的 `FiberNode`节点放入一个 Map 里，遍历剩余的新的`JSX`元素，然后从 Map 中去寻找能够复用的 FiberNode 节点，找到就复用
   找不到 就新增 。如果遍历完 ReactELement还有剩余的 FiberNode 就全部加进 `deletions`数组，最后统一删除

## 双端对比算法

指的是在新旧子节点的数组中，各用两个指针指向头尾的节点，在遍历的过程中，头尾两个指针同时向中间靠拢。
因此在新子节点数组中，会有两个指针，`newStartIndex` 和 `newEndIndex`。旧的也有`oldStartIndex ``oldEndindex`两个指针。

一次双端比较就是，每遍历到一个节点就比较一次四个节点。 匹配成功就更新双端的指针 。

### 为什么不用 双端 Diff

双端 Diff 需要向前查找节点，但是每个 FiberNode 节点上没有反向指针，即前一个 FiberNode通过 sibling 属性指向 后一个 FiberNode 只能单向，而不是反过来 ，因此改算法无法通过双端搜索来进行优化
